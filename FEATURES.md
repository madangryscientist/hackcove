## UI review workflow
- `ui-review-workflow`: check every pull request in a repo that uses the components for building its UI the UISlash way, with a rule check that fails the pull request and an advisory model review. How to reach it: a job with `uses: slashsuite/uislash/.github/workflows/ui-review.yml@main`, `secrets: inherit` and `permissions: { contents: read, pull-requests: write }`; the workflow is `on: workflow_call`. Source: `.github/workflows/ui-review.yml`
- `ui-review-inputs`: tune the workflow with its inputs: `runs-on` (the runner, default `ubuntu-latest`, another runner for private repos only), `paths` (globs of the app code to review, `!` excludes), `hackcove-repo` (the repository holding the rules, default `slashsuite/uislash`), `hackcove-ref` (its branch, tag or sha, default `main`), `self` (the caller is this repository), `build-rubric` (build `/ui/llms.txt` from the checkout instead of fetching it) and `llms-url` (the component reference, default `https://hack-cove.com/ui/llms.txt`). How to reach it: `with:` on the calling job. Source: `.github/workflows/ui-review.yml`
- `ui-review-secrets`: pass the workflow's optional secrets: `OPENCODE_API_KEY` (the model review's key; without it that review is skipped), `HACKCOVE_READ_TOKEN` (reads `hackcove-repo` while it is private) and `MOON_REMOTE_TOKEN` (a read token for the shared moon remote cache, used only by `build-rubric`). How to reach it: `secrets: inherit` or `secrets:` on the calling job. Source: `.github/workflows/ui-review.yml`
- `ui-review-rule-check`: fail a pull request, with a `file:line` annotation for each, when its added lines break a rule: `new-css` (a new stylesheet beyond the Tailwind and theme imports), `style-block` (a `<style>` block), `raw-colour` (a raw colour utility), `dark-variant` (a `dark:` variant), `styling-prop` (`className` or `style` on a component) or `duplicate-component` (a local component with the name of a component export). How to reach it: the workflow's `rules` job. Source: `tools/ui-review/src/rules.ts` `tools/ui-review/src/layer1.ts`
- `ui-review-model-review`: get an advisory review of a pull request's UI from the model `opencode/deepseek-v4.1-flash`, posted as comments; its findings never fail the pull request, and it is skipped, green, with no key, no changed app file or a model account out of credits, while a crash, a timeout, an unreadable reply or a missing reference fails it. How to reach it: the workflow's `review` job, run when `OPENCODE_API_KEY` is set. Source: `tools/ui-review/src/review.ts` `tools/ui-review/src/prompt.ts:2`
- `ui-review-check-by-hand`: run the rule check on a local diff; it exits 0 when clean, 1 on findings and 2 when it could not run. How to reach it: `bun tools/ui-review/src/check.ts --base <sha>` with `--head` (default `HEAD`), `--hackcove` (the rules checkout, default `.hackcove`) and `--paths`. Source: `tools/ui-review/src/check.ts` `tools/ui-review/src/args.ts`
- `ui-review-review-by-hand`: run the model review on a local diff, or print the prompt it would send. How to reach it: `bun tools/ui-review/src/review.ts --base <sha> --llms <llms.txt>` with `--dry-run` (print, send nothing), `--pr` and `--repo` (comment on that pull request), and the rule check's `--head`, `--hackcove` and `--paths`. Source: `tools/ui-review/src/review.ts` `tools/ui-review/src/args.ts`
